# CareerTrack – Student Career & Placement Management System

Frontend: HTML, CSS, **TypeScript**  |  Backend: Python + Django  |  Database: MySQL

```
CareerTrack/
├── backend/          Django project (API, database models, business rules, seed data, tests)
├── student-portal/   Website + student login/register + onboarding wizard + student portal
│   ├── src/          TypeScript source (edit these)
│   └── dist/         compiled browser files (generated by `npm run build`)
└── admin-panel/      Admin login + admin panel (separate folder, separate link, same layout)
```

## 1. First-time setup (Windows / Linux / Mac)
1. Install **Python 3.10+** and **MySQL** (with MySQL Workbench).
2. In MySQL Workbench run:  `CREATE DATABASE careertrack CHARACTER SET utf8mb4;`
3. Open a terminal in the `backend` folder:
```
python -m venv venv
venv\Scripts\activate          (Linux/Mac: source venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env         (Linux/Mac: cp .env.example .env)
```
4. Open `.env` and put your MySQL password in `DB_PASSWORD`.
   (To try the project without MySQL, set `DB_ENGINE=sqlite` in `.env`.)
5. Create the tables and the demo data, then start the server:
```
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

The forgot-password code is printed in the backend terminal (and shown on screen in development).

## 3. TypeScript (frontend)
The `dist/` folders already contain the compiled files, so the project runs without Node.js.
Install **Node.js** only if you want to change the code in `src/`:
```
cd student-portal          (and the same in admin-panel)
npm install
npm run dev                (rebuilds automatically while you edit)   or   npm run build
npm run typecheck          (checks the types only)
```
Never edit files in `dist/` - they are generated.

## 4. Run the tests
```
python manage.py test
```

## 5. How it fits together
* `placement/models.py` – tables (Student, Job, Company, Application, Notification ...)
* `placement/logic.py` – **business rules**: eligibility check, apply rules, one-offer placement policy, status changes
* `placement/views.py` – JSON API (`/api/...`), token login, validation
* Application tracking uses saved status history (`Applied` → `In Review` → `Shortlisted` → `Interview` → `Selected`) with `Rejected` and `Closed` as terminal outcomes. Admins update stages from Applications and schedule interview rounds there; the student timeline reads those saved events and interview records.
* `placement/management/commands/seed_demo.py` – demo data
* Frontend files call the API through `assets/js/core.js` (change `CT_API` there if the backend runs on another address).
* Uploaded photos and resumes are stored in `backend/media/`.

## 6. Automated notifications
Eligible, active students receive a notification when an admin posts a job. The admin's manual **Notify** action remains available and skips students already notified about that job. Creating an interview round notifies the applicant automatically.

After updating an existing installation, apply the notification metadata migration once with `python manage.py migrate`.

Run deadline reminders once daily. The command notifies eligible students who have not applied to jobs closing today or within the next two days, and records each reminder so reruns do not send duplicates:

```powershell
cd backend
.\venv\Scripts\python.exe manage.py send_deadline_reminders
```

**Windows Task Scheduler:** Create a daily Basic Task, choose a time, and set:
- **Program/script:** `C:\path\to\CareerTrack\backend\venv\Scripts\python.exe`
- **Add arguments:** `manage.py send_deadline_reminders`
- **Start in:** `C:\path\to\CareerTrack\backend`

**Linux/macOS cron:** Add a daily entry (adjust the project path and run time):

```cron
0 9 * * * /path/to/CareerTrack/backend/venv/bin/python /path/to/CareerTrack/backend/manage.py send_deadline_reminders
```
